# PlainTalk

让 LLM 把话说清楚：在用户端通过技能包或纯指令约束模型输出，使表达清晰、逻辑通畅，且不新增、不丢失事实。

当前版本号 v0.5。入口 1.6KB；四个职责模块按任务加载，普通短回答约 7.5KB，完整文档任务约 15.1KB，另附 CHANGELOG。v0.4 精简时六场景对照 5/6 通过，原版 1/6，无回退。技能包在 `skill/plaintalk/`，无每轮注入。

## 要解决的问题

LLM 的输出经常没错但不好读：一句塞三个概念、结论藏在第四段、术语不解释、套话比信息多、论证跳步。多数写作优化方案集中在删词汇层痕迹；PlainTalk 把重点放在信息组织与论证顺序，并把风格从形容词分解为六层可操作变量。

## 六层风格变量

风格不是形容词，是一组变量：调哪一层、怎么测出调没调、约束写进哪里。

| 层 | 管什么 | 规则落点举例 |
|---|---|---|
| 语气与人际 | 立场与温度：确定性、贴近度、直接性 | 按体裁定结论位置；不写说教收尾 |
| 组织与篇章 | 信息排列顺序与论证形状 | 结论前置、一句一义、判断与依据相邻 |
| 符号与格式 | 标点、间距、Markdown、缩写 | 标题用名词短语、中西文空格、标题层级不跳 |
| 语言层次与语域 | 词汇难度、句法复杂度、对读者的匹配 | 术语按读者解释、中英分轨 |
| 信息与熵 | 信息量与排列密度 | 四类空话判据、事实不增不减 |
| 语用与交互 | 言语行为选择与协作姿态 | 缺口声明或最多一问、不替读者补决策 |

完整分解表，含每层维度、可测量指标、控制手段与证据来源，留在项目私有设计文档，不随仓库发布。规则实现全部在技能包内。

## 目标与非目标

| 目标 | 非目标 |
|---|---|
| 泛化的清晰度与连贯性约束，跨场景 | 领域文体，包括公文、学术、营销、法律 |
| 中文优先，中英分轨 | 中英共用一套规则 |
| 纯 API 可用，不碰权重、不做微调 | 解码期干预、LoRA、SFT |
| 规则可验收，触发标记加改法加例外 | 感觉更顺了式主观调参 |
| 多形态出口，技能包、纯指令 | 绑定单一宿主 |
| 不改变事实，信息守恒红线 | 替模型补内容、补观点 |

## 技能包结构

```
skill/plaintalk/
├─ SKILL.md            入口：读取表、冲突优先级、使用边界、交付检查
├─ CHANGELOG.md        改动记录
└─ references/
   ├─ facts.md         事实：数字、范围、情态、状态、术语、缺口、推导
   ├─ structure.md     结构：结论、段落、标题、摘要、选材、文体骨架、示例
   ├─ expression.md    表达：直接陈述、空话、改写、语气、中文与 English 习惯
   └─ format.md        符号：保护区、标题形式、标点空格、列表表格、箭头
```

加载方式：入口的读取表是唯一索引，所有输出都读 `facts.md`，其余三份按任务触发。模块之间不互相引用，也不再有语言轨或文体分册。

## 安装与用法

- Agent Skill 宿主：任何扫描技能目录的宿主，把 `skill/plaintalk/` 整个目录放进宿主技能扫描根。
- 纯指令：把 `SKILL.md` 与入口触发表点到的模块一起贴进系统提示或项目指令；语言模块只附输出语言那一份。
- 改写草稿：给出草稿并说明按 plaintalk 改清楚；改写约束在入口与表达模块。
- 触发词：说人话、太绕了、看不懂、改清楚、精简、像人写的。
