# PlainTalk

让 LLM 把话说清楚：在用户端通过上下文约束，包括技能包、指令、场景包，控制模型输出的语言风格，使其清晰易懂、逻辑通畅，且不新增、不丢失事实。

当前版本号 v0.4.2。2026 年 10 月结构精简：13 个文件 43KB 压成 3 个规则文件 9.3KB（另 CHANGELOG）；六场景对照 5/6 通过，原版 1/6，没有回退。技能包在 `skill/plaintalk/`，按需加载，无每轮注入。

## 要解决的问题

LLM 的输出经常没错但不好读：一句塞三个概念、结论藏在第四段、术语不解释、套话比信息多、论证跳步。现有开源方案几乎全部集中在去 AI 味，也就是删词汇层痕迹，而讲明白需要的信息组织与论证顺序约束基本无人做。PlainTalk 占后者，并把风格从形容词分解为六层可操作变量。

## 六层风格变量

风格不是形容词，是一组变量：调哪一层、怎么测出调没调、约束写进哪里。

| 层 | 管什么 | 规则落点举例 |
|---|---|---|
| 语气与人际 | 立场与温度：确定性、贴近度、直接性 | 不替读者抢先下判断；体裁定基调；分受众校准 |
| 组织与篇章 | 信息排列顺序与论证形状 | 结论前置、一句一义、判断与依据相邻、长文骨架 |
| 符号与格式 | 标点、间距、Markdown、缩写 | 中西文空格、冒号纪律、标题层级不跳 |
| 语言层次与语域 | 词汇难度、句法复杂度、对读者的匹配 | 分级词表、完整语法短句、情态阶梯 |
| 信息与熵 | 信息量与排列密度 | 空话判据、指认对象密度自检、信息守恒红线 |
| 语用与交互 | 言语行为选择与协作姿态 | 两态发问、反说教收尾、指令与建议之分 |

完整分解表，含每层维度、可测量指标、控制手段与证据来源，留在项目私有设计文档，不随仓库发布。规则实现全部在技能包内。

## 目标与非目标

| 目标 | 非目标 |
|---|---|
| 泛化的清晰度与连贯性约束，跨场景 | 领域文体，包括公文、学术、营销、法律 |
| 中文优先，中英分轨 | 中英共用一套规则 |
| 纯 API 可用，不碰权重、不做微调 | 解码期干预、LoRA、SFT |
| 规则可验收，触发标记加改法加例外 | 感觉更顺了式主观调参 |
| 多形态出口，技能包、指令、场景包 | 绑定单一宿主 |
| 不改变事实，信息守恒红线 | 替模型补内容、补观点 |

## 技能包结构

```
skill/plaintalk/
├─ SKILL.md            八条约束 + 任务契约 + 场景加一条 + 格式 + 交付前五问 + 不要用
├─ CHANGELOG.md        改动记录
└─ references/
   ├─ zh.md            中文表层规则：六种失效、抽象词、格式、该保留的
   └─ en.md            英文表层规则：六种失效、格式、该保留的
```

加载方式：`SKILL.md` 随技能加载；语言轨按输出语言读一份。场景提示已经并进 `SKILL.md`，不再单独路由。设计纪律只剩一条：每条约束都要能指到一个会咬人的失效，指不到就不写。

## 安装与使用

- Agent Skill 宿主：任何扫描技能目录的宿主，把 `skill/plaintalk/` 整个目录放进宿主技能扫描根。
- 纯指令：把 `SKILL.md` 正文贴进系统提示或项目指令；语言轨按输出语言附一份。
- 改写草稿：给出草稿并说明按 plaintalk 改清楚；改写约束在 `SKILL.md` 第 7 条与场景提示里。
- 触发词：说人话、太绕了、看不懂、改清楚、精简、像人写的。
