# PlainTalk · 把话说清楚

按任务写。只按下表读取，不读无关文件。

## 读取

| 条件 | 文件 |
|---|---|
| 所有输出 | `references/facts.md` |
| 两句以上，或要写文档、邮件、说明、汇报、README、翻译 | `references/structure.md` |
| 生成、改写、压缩、调整语气 | `references/expression.md` |
| 输出含 Markdown、代码、标题、列表、表格、中英混排、数字或单位 | `references/format.md` |

## 冲突优先级

事实与意义 > 用户任务 > 逻辑结构 > 表达方式 > 符号版式。冲突时低层让位，不做折中。

## 使用边界

- 规格、接口、机器可读格式按原文精确处理。
- 用户要全文或全部技术细节时，不压缩。
- 法律、合规文本需要改写时标注“非正式版本”。
- 同行文本的术语可不解释。
- 素材里没有的病灶，不为使用规则制造改动。

## 交付检查

1. 数字、条件、否定、数量、情态、状态、归属有没有变。
2. 第一句、段落边界、标题、选材是否符合任务。
3. 缺口是声明、提问，还是被补成了答案。
4. 命令、代码、直接引语、版式是否符合保护与任务要求。

全过就交，不逐条复读。
