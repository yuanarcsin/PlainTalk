# 语气层 · 立场与温度

> 语言共用层。管说话者对读者与内容表现的立场：多确定、多贴近、多直接。
> 不管说什么（内容层的事），也不管信息怎么排（structure.md 的事）。

## 一、先定基调

基调由文本类型决定，动笔前先判一次；不要一律"中立礼貌"：

| 文本类型 | 基调 | 保留什么 |
|---|---|---|
| 观点类（博客、随笔、个人总结） | 有立场 | 作者的观点、不确定、混合感受、幽默、旁枝 |
| 参考/技术/事实类（文档、报告、README） | 中立平实 | 不添加；让事实与约束自己说话 |
| 对话回复 | 协作 | "一起拆问题"的姿态，不是"我来告诉你" |

用户给了风格样本时，**样本优先于默认规则**：先读样本的句长、用词、标点、开头与连接方式，
照它对齐；样本用破折号就保持大致相同频率。删痕迹只是一半，改完仍要像人写的。
（出处：blader-humanizer Voice）

## 二、确定性：不替读者抢先下判断

- "很清楚 / 说明了 / 显然 / 真正" → 换三步：观察到什么 → 能归纳出什么 → 这个归纳落在哪。
- 给强判断的前置条件，至少满足一条：前文提过这个猜想（本段是回指）；同段有交叉验证的
  evidence；引用了具体模块、代码、issue、trace、指标或实验结果。
  （出处：technical-writing Core Stance；与 structure.md §二 同纪律）
- hedging 分清两种：表达真实不确定的（"我认为 / 大概 / 暂时"）**保留**；
  不承载信息的装饰性 hedging（"may possibly suggest that it could" 式堆叠）删到最多一个。
  （出处：no-ai-slop；en 失效清单 #11）

## 三、分受众校准

- 面向评审/上级：少下定论，多给推演路径；少用绝对化副词，多用"先 / 可以 / 暂时 / 顺着这个观察"；
  少写审判式句子，多写解释式句子。
- 面向同事/同行：术语是共同语言，不白话化（见 SKILL 层 3）；姿态是平级讨论，不是汇报。
- 面向新手/大众：术语密度降低、首现给锚（S3）；素材没给定义就不补，列待补清单。
- 结尾：少写"作者赢了"的结尾，多写"读者可以继续往下跟"的结尾。

（出处：原 structure.md §四，迁入本文件）

## 四、温度：该保留的不是错

- 作者自己的评价、承认、旁枝是断言或声音：R12 判为素材断言的就保留，删掉等于替他做取舍。
- 不把强观点、直白表达、幽默换成"更安全、更专业"的说法。
  粗糙但有真声音的草稿，改完仍该是同一个人。（出处：no-ai-slop）
- 反向同样成立：不给中性素材加温度——不给中性数据加情绪定性（层 0 第 5 条）。
