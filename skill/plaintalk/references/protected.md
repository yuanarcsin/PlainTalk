# 保护区与不介入区

> 改写类任务（用户给你一段草稿）必读。这里的东西**一个字都不动**。

## 一、五类不可动对象

| 类别 | 范围 | 常见失手 |
|---|---|---|
| **数字与单位** | 定价、折扣、名额、日期、时间、统计量、指标 | "约 42%" 改成 "超过四成"（精度漂移）；"4.2 s" 改成 "42s" |
| **限定与条件** | "仅在 X 时成立""必须提前 3 个工作日""依赖 Y 完成" | 为了句子短而把条件从句删掉 |
| **风险与不确定性** | 待验证／未收敛／暂定／尚未确认／据说／可能 | 把"暂定分页解决"写成"采用分页解决"；把未决补成一个漂亮答案 |
| **标识符** | API 端点、文件名、函数名、字段名、行号、URL、专名 | 同义词替换（《X 工作术》→"这门课"）；把 `retry_count` 译成"重试次数" |
| **原话与结构** | 引用块、代码块、行内代码、命令、表格数据行、公式、日志 | 顺手统一标点；把表格拆成 bullet；把代码注释"改通顺" |

## 二、改完之后逐项核对

三件事逐项做，不是"整体看一遍"：

1. 把原文的保护区清单抄下来，逐条在输出里搜——**必须逐字存在**。
2. 把输出里出现的每个数字与专名回原文搜——**必须找得到出处**。
3. 把原文的 hedge（约／可能／待／未决／暂定）数一遍，输出里**不能变少**。

## 三、容易误杀的情况（这些要放行）

- **术语密度高的专家段落**：读者是同行时，术语是共同语言，白话化是杂讯。
- **长但只讲一件事的句子**：单一条件 + 并列结果，拆了会丢条件的作用域。
- **承载比较功能的比喻**："像图书馆借阅排行"解释 LRU，删了读者失去支点。
- **口语话语标记**：对话场景里的"说白了"，后面紧跟可执行信息时不是空转句。
- **管道符表格**：4 项 ×2 维的对比，表格比 bullet 更省读者力气。
  （"表格一律拆成 bullet"的理由是**框线字符表格**在手机上会烂，不是 markdown 表格。）
- **作者主动写下的归属式论断**："在学界已被广泛采用"。它空洞，但那是作者选择说的话。

## 四、什么时候整个技能都不要用

- 规格书、接口定义、机器可读格式（JSON/YAML/CSV schema）：精确 > 好懂。
- 法律、合约、隐私政策：用字有法律效果；改写必须标注"非正式白话版"。
- 用户明确要原文、要全量技术细节。
- 代码、命令、日志、报错原文。
- **素材里没有的病灶，不要为了用规则而制造改动。** 局部合规、全局变差是本项目
  实测到的主要失效方式之一。
