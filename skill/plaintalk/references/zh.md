# 中文轨 · 表层规则

> 只在输出是中文时读。英文轨见 `en.md`。
> **中文和英文的病灶不一样，改法不一样，不要把一种语言的规则套到另一种上。**
> 中文头号病灶是"一句话塞三个概念、没有断点"；英文是"无主被动语态 + 名词堆叠"。

## 一、中文特有的失效清单

| # | 现象 | 判据 | 改法 |
|---|---|---|---|
| 1 | **一句塞多个概念** | 句长 ≥40 字且含 ≥2 个逗号，或 ≥3 个逗号 | 按语义断点拆成 2–3 句，每句一个命题 |
| 2 | **英文直译腔** | `real/realize/reality` 译成"现实/真实"、`issue` 译成"问题"、`policy` 译成"政策" 而语境其实是"实际上/注意到/议题/策略" | 按中文习惯重写整句，不是逐词替换 |
| 3 | **空评价词替代约束** | "很重/很轻/很顺/相当令人鼓舞/效果显著" 且句中无可指认对象 | 换成具体约束、具体风险、具体影响；没有就整句删 |
| 4 | **对立句法造强调** | "不是…而是…"、"不在…而在…" | 整段最多一次。承载排除性信息（真的排除了一个归因）时保留 |
| 5 | **过场句在主持文章** | "聊到这里""继续往下看""先把这件事单独拿出来说""最后用一句话收住" | **删，不要改写成另一句过场话**。判据：删掉后事实、论证、结构都不受影响 |
| 6 | **术语漂移** | 同一事物在文中出现两个名字（"筛选条件"/"过滤规则"混用） | 钉住一个词，全文统一；已确定的词系优先复用 |
| 7 | **抽象抢戏词** | 见下方黑名单 | **逐句重写，不是逐词替换**。原句里只有黑话词承载信息时，整句通常没信息 |
| 8 | **段首零主语评论** | "不得不说，""必须承认，" 开头 | 删或补出主语 |
| 9 | **序数词空标题** | "一、现状分析""二、结论" | 标题写成一句带内容的话，≤25 字 |
| 10 | **顿号堆叠** | 一句内 ≥3 个顿号 | 拆句或改列表 |
| 11 | **破折号插入语** | `——` 每 300–500 字 >1 次，或同段连续 | 改逗号或独立短句 |
| 12 | **引号不统一** | 中英文引号混用 | 中文引用统一用 `「」` |

### 抽象抢戏词黑名单（附替代写法）

```
生态 / 生态位        → 列出具体依赖关系、用户类型或集成方
赋能                 → 让用户能 X / 把 X 能力开放给 Y
闭环                 → X 之后 Y 也接进去了
抓手                 → 我们能改的那一个变量是 X
心智                 → 用户第一次看到 X 时会怎么想、怎么操作
链路打通 / 打通      → A 现在能调用 B / A 写入的数据 B 也能读到
沉淀                 → 记录到 docs/X / 整理成 skill、runbook
落地                 → 在 A 模块实现 / 在 B 业务用上
底座 / 底层逻辑      → 基础设施层是 X / 这件事成立的前提是 Y
收口                 → 所有 X 都走 Y 一个入口
加持                 → 加了 X 之后能 Y
```

### 评价腔 / 主持腔

```
很值得 / 非常值得    → 给具体理由：在哪个维度上值得
极致 / 丝滑 / 顺畅   → 给具体指标或具体约束：延迟降到多少、哪步原本卡
深度集成 / 一站式    → 给集成点范围 / 在 A 入口能完成 B、C、D
颠覆 / 重塑          → 默认不用；要用得有 before/after 对比
```

## 二、实测口径

**成立的信号**（简体中文 5 个模型 283 万字语料，AI / 人类每千字倍率）：
空转句引列表冒号 9.4×；拟人化喻体 7.3×；段首零主语评论 4.4×；
提示语冒号 3.8×；翻案腔 3.4×；起手式"说白了" 3.2×；序数词小标题 3.1×；
破折号 3.0×；相邻 2 句同构 2.0×；顿号罗列 1.8×。

**方向相反的是另一侧**：数字密度 AI 6.34 / 人类 17.92（差 2.8 倍），
时间锚点 0.69 / 1.78。
→ **AI 文本的核心毛病是具体信息少，不是花样多。只删套话，删完仍然是空的。**
变好靠的是作者提供事实，不是模型补事实。

**跨模型差异**：破折号每千字 DeepSeek 5.16、Claude 4.25、Kimi 2.32、Gemini 0.51、GPT 0.11。
→ 表层阈值换模型要重测。

## 三、中文该保留的东西（防误杀）

句型有具体事实撑着就放行：

- 「这次的问题不在模型容量，而在标注一致性——三名标注员的 Kappa 只有 0.41」
  → 对立结构承担排除归因 + 紧跟数据，**保留**。
- 「如果报名数在开课前 3 天仍未达到 40 人，就把场地从报告厅改到 204 教室，预算从 600 元压到 200 元」
  → 58 字但只讲一件事（单一条件 + 两个并列结果），**不拆**。拆了会丢条件的作用域。
- 「缓存的淘汰顺序就像图书馆的借阅排行——热门的书总在被取走」
  → 喻体承载机制说明，**保留**。
- 「说白了就是缓存没命中，你查一下 `cache.get()` 的返回值」
  → 日常对话里的话语标记 + 后面紧跟可执行信息，**保留**。

## 四、格式与符号

| # | 现象 | 判据 | 改法 |
|---|---|---|---|
| 13 | **中英文之间无空格** | 汉字与拉丁字母/单词紧邻 | 之间加一个半角空格；例外：官方产品名按官方写法（如「豆瓣FM」） |
| 14 | **中文与数字、数字与单位之间无空格** | 「5000元」「10Gbps」 | 加空格：「5000 元」「10 Gbps」 |
| 15 | **全角半角标点混用** | 中文语境出现半角逗号/句号/冒号 | 统一全角；引号统一 `「」`（见 #12） |
| 16 | **缩写首现无全称** | 缩写直接出现 | 首现给全称 + 缩写，其后统一用缩写；素材没给全称就列待补清单（S3），不编 |
| 17 | **emoji 与装饰符号** | 技术文档/报告里出现 emoji | 不用；对话场景随从宿主与用户习惯，不主动加 |
| 18 | **标题层级跳级或装饰堆叠** | 层级跳级（H2 直下 H4）；整段加粗 | 层级不跳；加粗只给关键术语与结论；格式元素服务结构（R11） |

（出处：13–15 chinese-copywriting-guidelines；16–18 项目设计，与 S3/R11 同纪律）

## 五、层次与语域

- 先定读者层级再定术语密度与解释深度：同行 / 大众 / 新手。
  同行之间术语是共同语言，不白话化（SKILL 层 3）；把同行文档降成白话是误杀。
- 面向大众的文本优先常用词；书面语或技术词首现给锚（S3）。
  中文等级参照《国际中文教育中文水平等级标准》（三等九级），阈值未实测，作方向参照不作硬限。
- 句法层：长句按 #1 拆；但**不电报化**——单条件复句、主谓完整就不拆（见 §三 防误杀）。
- 语态与人称：段首零主语评论补主语（#8）；机制陈述优先「A 做 X」，少用「X 被 A 做」。
