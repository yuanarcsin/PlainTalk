# 定向包 · 汇报讲稿 / 口播稿 / 答辩陈述

> 命中条件：文字会被**念出来**，听众用耳朵接收，不能回看。
> 与文档相反：这里**听觉优先**，牺牲书面紧凑度换即时可懂。

## 一、听觉友好硬规则

1. **短句为主。** 目标平均 ≤20 字，单句不超过一口气能说完的长度。
2. **禁止括号嵌套**（"（也就是原来的三倍）"念出来是灾难）。
3. **禁止破折号插入语。** 需要补语就另起一句。
4. **数字要带口径。** 念"从 200 降到 130"不够，要念"单人日处理量从 200 条降到 130 条"。
5. **一组一段。** 每个数据组单独一句/一段，听众才有落点。
6. **允许并鼓励结构预告。** "接下来四组数字，每组都先说改之前、再说改之后"——
   在文档里这是空转句，**在口播里是听众唯一的导航**。
   判据：这句是否替不能回看的听众建立了位置感。是 → 保留。
7. **结论第一句。** 讲稿的第一句就该是这页要听众带走的那句话。

## 二、这个场景最容易犯的错

- **加评价。** "先说一个不太好听的数字"——幻灯片上没有评价，讲稿加了就是新增。
  听众会以为这是数据本身的性质，而它只是修辞。
- **加因果。** 幻灯片并列写"返工 11→2 小时"和"交付量 3000→3510"，
  讲稿写成"返工少了以后，交付量涨上去了"就是替素材建立因果。
  **例外**：素材标题自己写了因果（"交叉核对**让**周交付量提升 17%"），
  此时复述该因果不算新增，但不得再补第二条因果链。
- **重算数字。** 幻灯片给的是 17% 和 3510，讲稿不得算成"约六分之一""三千五左右"。
- **照本宣科。** 逐条念完不算讲稿。讲稿要有"为什么先看这个"的顺序感，
  但顺序感只能靠连接词，不能靠新增信息。

## 三、时长与字数

| 时长 | 字数（中文） |
|---|---|
| 30–60 秒 / 页 | 150–250 |
| 90 秒 | 250–380 |

超时长先砍例子，不砍结论，不砍口径说明。
