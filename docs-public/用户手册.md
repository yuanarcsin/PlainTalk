# PlainTalk 用户手册

## 30 秒版

PlainTalk 让模型把话说清楚。它不教模型写什么，只约束怎么呈现：结论先给、一句一件事、术语按读者解释、缺口不填、素材事实不增不减。

这里的素材，指你提供给模型的事实材料。PlainTalk 不改事实，只改说法。

适合写作、改写、文档、邮件、说明与汇报。不适合规格、接口、法律原文，也不改代码和日志原文。

## 安装

### 支持 Agent Skill 的宿主（如 WorkBuddy）

1. 把 `skill/plaintalk/` 整个目录放进宿主的技能扫描根。
2. 确认目录里有 `SKILL.md`、`references/zh.md`、`references/en.md`。
3. 新开一个会话，说“说人话”，或“用 plaintalk 改这段”。

### 纯指令

把 `SKILL.md` 正文贴进系统提示或项目指令。输出中文再附 `references/zh.md`，输出英文附 `references/en.md`。两份语言轨不要同时贴，规则会打架。

## 怎么触发

直接说：

- 说人话
- 太绕了
- 看不懂
- 改清楚
- 精简
- 像人写的

也可以点名任务：写 README、写邮件、写说明、写汇报、改周报。没有触发时，加一句“用 plaintalk”。

## 它会做什么

1. **事实不动。** 数字、单位、条件、约数、标识符原样；不补例子、数据、动机、因果，也不补素材没有的结论。
2. **结论先给。** 说明、文档、邮件把答案放第一句；叙事、法律、规格按体裁。
3. **一句一个主旨。** 需要回读的句子拆开；指代要能找到对象。
4. **术语按读者解释。** 读者是同行可以不解释；素材没定义就换词或列为缺口。
5. **缺口不填。** 素材没给的值、条件、配对方式，写“材料未说明”或问一句；“未定／暂定／尚未”原样保留。
6. **改写只删空话。** 数字、条件、机制、归属断言即使读起来空也要留；删完不用“本次更新……”这类总括句补位。
7. **长度按任务。** 低于下限先在素材内展开，仍不够就交实际长度并写“素材只支持 N 字”；超过上限就删，不靠加句。
8. **不替读者定重要性。** “值得注意”“标志着”不是禁词；有具体对象可以用，空泛时才删。

## 三个例子

### 对话

**不用 PlainTalk**：缓存失效是一个复杂的问题，涉及多个层面的因素，需要综合考虑。

**用 PlainTalk**：缓存老失效，最可能是过期时间太短。材料只给了 5 分钟，没给访问频率；如果是高频数据，5 分钟会反复回源。要不要调到 30 分钟，得看你们的写入频率。

### 文档

**不用 PlainTalk**：本系统赋能业务闭环，打造一站式体验。

**用 PlainTalk**：客服在一个页面里完成退款、换货和备注，不用再跳三个后台。

### 改写

**原文**：本次更新从根本上重塑了我们对标注流程的认知，标志着团队协作迈出了坚实的一步。双人交叉核对机制——不仅仅是流程上的调整——为数据质量注入了新的活力。

**改写**：双人交叉核对把错标率从约 4% 降到 0.7%。学界已广泛采用类似流程。

## 不适用

- **规格、接口、机器可读格式**：精确优先，不为了好读改写。
- **法律、合规文本**：用字有法律效果；要改，标注“非正式版本”。
- **同行之间**：术语是共同语言，不强行白话。
- **代码、命令、日志、报错原文**：逐字不动。
- **素材里没有的病灶**：不要为了用规则制造改动。

## 常见问题

**会不会把专业术语删掉？**
不会。术语按读者解释；读者是同行可以不解释。素材没定义时，换词、不用，或列为缺口。

**会不会为了短删事实？**
不会。素材优先于下限。低于下限时先在素材内展开；仍不够，交实际长度并写“素材只支持 N 字”。

**英文支持吗？**
支持。英文读 `references/en.md`，中文读 `references/zh.md`；两套规则不混用。

**能改代码或法律文本吗？**
代码、命令、日志原文不改。法律、合规文本可以改，但要标注“非正式版本”；正式文本不要用。

## 版本与边界

当前版本 v0.4.2。改动记录见技能包 `CHANGELOG.md`。

PlainTalk 约束写法，不改事实，也不替代你的判断。结论来自受控测试，不保证每条输出都达标。

遇到问题，先看 `SKILL.md` 的八条约束；还不对，再查 `references/zh.md` 或 `en.md` 的表层规则。
